# May 9, 2026 — Research Log

## Morning: Graph Neural Networks

Spent 2 hours going deep on [[Graph Neural Networks for Knowledge Reasoning]]. The R-GCN architecture is the right choice for typed relation learning in knowledge graphs — the per-relation weight matrices are essential because "BERT *uses* Transformer" and "BERT *is_a* language model" carry fundamentally different semantic information and shouldn't be aggregated with the same weights.

The connection to attention in Transformers ([[Transformer Architecture]]) is elegant: Graph Attention Networks (GATs) are basically self-attention over a graph neighborhood instead of a sequence. Same mathematical intuition, different topology.

## Embedding Experiment

Compared `text-embedding-004` (Gemini) vs `bge-m3` (local) on 20 of my notes:

| Metric | text-embedding-004 | bge-m3 |
|---|---|---|
| Avg similarity (related notes) | 0.82 | 0.78 |
| Avg similarity (unrelated notes) | 0.31 | 0.35 |
| Separation (delta) | **0.51** | 0.43 |
| Latency per embedding | 120ms (API) | 80ms (local) |

Gemini embeddings show better separation between related and unrelated content — the discriminability is ~18% higher. Worth the API call latency for a knowledge retrieval system.

## Graph Visualization Notes

Looking at the minoverse knowledge graph UI — currently only shows resource-level nodes. The ideal graph should:
- Show **concept entities** as nodes (Transformer, BERT, RAG, etc.)
- Show **relations** as typed, directed edges with labels
- Allow filtering by entity type (concept, model, framework)
- Show **resources** as secondary nodes linked to the concepts they discuss

This requires Phase 4's entity promotion + relation generation pipeline to be fully working with high-quality LLM output.
